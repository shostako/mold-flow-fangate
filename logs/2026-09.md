### grid_shift_mm（Codex P2 の本質的指摘から）

φ23 の半径 11.5 で y レベル（ゲート端 56.5 / 製品エッジ 66.5 / 額縁境界 81.5）が 1mm 格子のセル中心に
ちょうど乗り、境界セルが丸ごと片側に落ちて**既定解像度の製品描画が井戸径に連動してずれる**
（表示原点 +0.5mm、額縁/内側 1 行誤配分 ≈ −0.855 cm³）。当初は厳密検証テストを 0.5mm 格子に退避して
「回避」したが、Codex に「デフォルト経路の退行を検出せず回避している」と図星を突かれた。
→ 製品エッジがセルエッジに乗るよう下側パッドを `(−y_edge) mod cell` だけ伸ばす `grid_shift_mm` を
config のプロパティ連鎖（y_axis_mm の起点）に導入。退避テストを既定格子に復帰、井戸 φ20/21/23 で
製品ラスタ同一の回帰テストを追加。

- ▽解析メンバーシップは井戸円を除外する（builder は井戸を後塗り。h=h_max で頂点が井戸接点セルに触れる）

## 2026-09-11 計量追従の race 修正 v0.7.3（PR #14、sim PR #87 と相互移植）

squash マージ（main 306f427）。sim 側は PR #87（v0.41.1）で同内容、向こうのユーザー確認でマージ。

- 原因: 計量欄の未編集判定が「前回の自動値と今の値の一致」。形状ウィジェットの連打で前の rerun の新値がブラウザに届く前に
  次の rerun が始まると、ブラウザの古い値が session_state に書き戻され「編集済み」と誤判定 → 追従が黙って止まる。
  AppTest（逐次）では再現せず、値の一致（199.80 = t0.65 の体積）から特定
- 修正 1（初版）: on_change フラグ。→ Codex P1: Streamlit は script 本体より先に「前回の状態と違う widget 値」の on_change を
  発火するので stale echo でもフラグが立つ。複製上の変異版（無条件フラグ）で `set_value(旧自動値)` により再現
- 修正 2: 届いた値が自動値履歴（直近 32 件）のどれかと一致すれば echo として除外。テストは session_state 直書きをやめ
  `set_value(旧自動値)` で本番と同じコールバック経路（1 rerun 遅れ・2 rerun 遅れ）。実ブラウザで幅の＋を 120 ms 間隔で
  6 連打しても追従が続くことを playwright で確認
- 修正 3（sim 側 Codex P2 の移植）: 編集後に二相 OFF→ON で widget の session_state が消え、フラグだけ残って number_input が
  min の 0.01 で再登場。編集値を `mfs_shot_volume_user_value` に写して復元
- 修正 4: 二相マップのタイトル `.0%` → 100% 未満は floor で小数 1 桁、nan は "nan%"（sim 側 Claude レビュー）。
  計量 < キャビティ体積なら caption に不足量と「→ ショートショット」
- レビュー: Codex は inline 2 件（P1/P2）、@claude は指摘なし相当（P3: 履歴深さの根拠コメント）。
  監視の罠 2 つ: 自分の inline 返信が review として commit=HEAD に付き「再レビュー済み」と誤判定／claude[bot] 自身の
  コメントで issue_comment run が 1 本 skipped で立ち「完了」と誤読。run ID とコメント ID を名指しで追う形に張り直した
- 425 passed。実ブラウザ確認は playwright（`get_by_role("spinbutton")` でヘルプボタンとの衝突回避、checkbox は
